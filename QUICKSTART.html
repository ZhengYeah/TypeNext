TypeNext

Continue writing in a supported textbox — with a local model or an approved API.

Experimental, unsigned build. The Windows executable cross-compiled and core tests passed. The Windows interface, DPAPI runtime and real provider accounts were not live-tested here. Use disposable text first. This is a UI Automation helper, not a native IME; application support depends on its accessibility text provider. See the verification report, including the old-toolchain caveat.

Upgrade from 0.1.1

Quit the old TypeNext using its tray menu (closing the main window only hides it). Extract this release and start its TypeNext.exe. Existing settings and shortcuts are preserved; remote mode remains disabled until you explicitly approve it.

Connect an API

  1. Open API settings… in TypeNext.
  2. Choose OpenAI, DeepSeek, OpenRouter or Custom OpenAI-compatible, then click Use preset.
  3. Enter the exact Model ID offered by your provider and paste your key into the masked API key field.
  4. Check Allow remote HTTPS API requests. Leave automatic remote requests off initially.
  5. Click Test API (sample) and approve the displayed endpoint. This saves the connection and sends only a fixed sample, which may incur a charge.

Keep inference local

Install/start Ollama separately and pull a model, for example:

ollama pull qwen3:4b

Use the Ollama local preset or these settings:

Protocol: ollama
API URL: http://127.0.0.1:11434
Model: qwen3:4b

Click Test model. Remote permissions and API keys are not required for an ordinary local Ollama server. Ensure the chosen server/model does not forward requests upstream.

Try a completion

Open the built-in test pad, place the caret at the end of its paragraph, and use your Suggest shortcut. Review the completed suggestion before accepting. The default shortcuts are unchanged:

ActionDefault
Request continuationCtrl + Shift + F9
Accept finished suggestionCtrl + Shift + F10
Pause / resumeCtrl + Shift + F11
DismissEsc

Use Shortcuts… to resolve a conflict; unavailable keys do not prevent startup. Tab acceptance is optional. Commit Chinese IME composition before requesting or accepting a suggestion.

Check your applications

Click Inspect in 3s, switch to your textbox and place the caret without selecting text. The inspector shows what the accessibility provider exposes and does not send it to a model. Approving an executable permits access; it does not guarantee compatibility. Typora, WeChat, Word and VS Code still require live testing on your PC.

What leaves your computer?

Remote completion sends the bounded text before and after your caret (defaults: 1,000 and 200 characters), a fixed completion instruction and generation settings to the approved endpoint. It does not upload screenshots, the full application tree or the clipboard. Your provider receives normal network/account metadata and may process or retain submitted content according to its own policies.

Remote automatic completion requires both the main Automatic suggestions setting and the separate Allow automatic remote requests permission. Automatic remote starts are at least three seconds apart; this is not a spending cap. Cancellation does not guarantee a provider stops billing.

Keys and compatibility

Saved keys are encrypted using current-user Windows DPAPI and associated with the exact request URL. Leave the key field blank to keep a saved key; use Remove to delete it locally. An environment-variable name can be used as a fallback. Removing a local key does not revoke it with the provider. No protection against malware already running as your account is claimed.

This build speaks Ollama and OpenAI-compatible Chat Completions, using Bearer authentication. Native Anthropic Messages, Responses-only APIs, arbitrary custom headers and APIs requiring query parameters are not implemented. HTTPS certificate validation is enforced; remote HTTP, redirects and HTTP proxies are disabled.
